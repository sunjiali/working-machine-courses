# 质量审计 · 对照 @DilumSanjaya 成品标准

审计日期：2026-10-24 夜。审计对象：服务器硬件交互课（`~/workspace/server-hardware-course/`）、继电器元件课（`~/workspace/knowledge-motion-cases/relay/`）。
标准来源：`~/workspace/research_notes/dilum-sanjaya-study.md` + Learn Arduino 站点一手文本（站点自述：interactive 3D board、16 节免费课、进度 0/16、Serial monitor、"Try it yourself" 自由练习区）。
审计方法：读两件产品的全部代码与文档；无头 Chrome（/opt/meta-chromium/chrome）实机驱动两页——点完服务器课 6 步导览、继电器课 4 步导览、触发粘连故障，截 7 张关键状态图（存 `~/workspace/server-hardware-course-artifacts/quality-evidence/`），并回读两页模型输出核对。两页实测均 0 控制台错误。

**总判断（先说结论）**：两件产品的「内核」是达标的——单一纯函数模型驱动全部读数，实测严丝合缝（服务器满负载 322 W / 64.4 °C / 14,689 RPM，与既定基线分毫不差；继电器粘连态控制侧 0 mA、负载侧仍 120 W，本课核心论点在模型里成立）。不达标的是「成品层」：**没上线、3D 没有光影、打开是关机状态、内容量只有对标的零头**。Dilum 的帖子公式是「作品链接 + 60 秒高密度录屏」，这两件产品现在一件都接不上这个公式——不是内容不行，是还没成为「产品」。

## 一、六维评分表

评级口径：**达标** = 与 Dilum 成品同级；**接近** = 骨架对、差一轮打磨；**不达标** = 结构性缺失，补课不是微调。

### 产品 A：服务器硬件交互课

| 维度 | 评级 | 证据 |
|---|---|---|
| ① 上线可访问 | **不达标** | 无任何公开 URL；只能本地 `python3 -m http.server` 打开（README 明写 file:// 会被 module CORS 拦）。Dilum 的 Learn Arduino 是任何人点开就能玩的 vercel 站。没有链接，X 发帖公式的最后一环（贴直链）不存在。 |
| ② 视觉质感 | **不达标** | 代码实查：全页 **0 处阴影**（castShadow/receiveShadow/shadowMap 均为 0）、无环境贴图（无 PMREM/RoomEnvironment）、无色调映射（无 ACES）；全部几何由一个 BoxGeometry 辅助函数 + 4 处 CylinderGeometry 拼出，材质为纯色 MeshStandardMaterial。截图实证（server-1/4）：机器无接触阴影、像漂在无限米色网格上；特写里 DIMM 是纯蓝长方块、散热器是灰平板、主板丝印字号大得像玩具。UI 外壳（奶油纸讲义风布局）本身整洁，那部分接近；但被拍摄的主体——3D 机器——是低多边形平面着色，与 WareTrack 的等距 3D 场景不是一个量级。 |

| ④ 内容完整度 | **接近** | 结构成体系：7 部件讲解 + 6 步开机时序 + 3 节课（讲解+导览+题+big idea）+ 实验室 + RAID 模拟器，不是单点演示。但量只有对标的零头：Learn Arduino 16 节课带进度计数，这边 3 节课一坐到底；部件只覆盖 7 个，无第二台机型、无进阶线。结构达标、体量不达标，综合接近。 |
| ⑤ 细节真实性 | **接近** | REFERENCES.md 是真功夫：Dell R750/R760、HPE DL380 Gen11、Supermicro 官方手册与实拍三档溯源，取舍全部明写（盘位 8 仓实装 4、内存 16 条 vs 真机 32、LCD 位置简化、罩掀开是教学处理）。未发现未披露的事实错误。硬伤在呈现层：风扇叶轮远看是星形/米字形（截图 server-1），不像双转子扇叶；特写丝印字号失真（server-4）；模型数值是手感校准的教学近似、非任何机型实测（已披露）。 |
| ⑥ 演示就绪度 | **不达标** | 打开第一帧 = **未上电**的静止整机：风扇不动、读数全静、机器只占舞台约 1/3，余下是大片空网格（server-1）。Dilum 的首帧是运行中的完整仪表盘+3D 场景。录制管线本身是通的（页内时钟逐帧录制、确定性帧率），但录什么的问题没解决：宽镜头稀疏、特写又把机器裁出画外（server-4 满负载特写里风扇墙不在画面内）；且现有演示视频录的是 v3 精修前模型、未按最终模型重录。 |

## 二、关键差距清单（按对「能不能发帖」的影响排序）

1. **两件产品都没有公开链接**（A①/B①）。Dilum 公式的收尾是主帖贴直链、读者点开就能玩；没有 URL，帖子只能发录屏、转化链断在最后一环。这是唯一的「一票否决」项，且修复成本最低。
2. **服务器课 3D 没有光影**（A②）。0 阴影 + 无环境反射 + 无色调映射，决定了任何镜头录出来都是「低多边形习作」观感。WareTrack 的画面说服力一半来自渲染质感，这一项不补，其他打磨都被它压住。
3. **打开是关机状态**（A⑥/B⑥）。两件产品首帧都是待机全零：服务器课未上电、继电器课触点分开。Dilum 首帧即运行中。访客和录屏观众的前 3 秒看到的是「一台没开机的机器」。
4. **服务器课舞台构图稀疏**（A②/⑥）。整机只占舞台约 1/3，背景是无限延伸的空网格地面，没有场景（机房/机柜/桌面）托住主体；特写镜头又走向另一极端，把整机裁出画面。
5. **内容体量只有对标的零头**（A④/B④）。服务器课 3 节 vs Learn Arduino 16 节；继电器课是单节课。Dilum 的账号靠「一门持续更新的课」立住（后续还有多语言、schematic 等更新帖形成闭环），单点内容发一条帖就烧完了，没有「更新帖」的燃料。
6. **只能跟着导览走，不能自己动手**（A③/B③）。Learn Arduino 有 "Try it yourself"：自己接线、运行、看监视器输出。我们的交互是「按顺序点下一步 + 拧实验室旋钮」，缺一个自由玩耍区，也缺继电器课的互动题。
7. **呈现层细节硬伤**（A⑤/B②）。风扇叶轮星形化、丝印字号玩具化、继电器课「负载电流」读数被小地图卡裁切——都是特写/截图时会被一眼看到的小伤，单独看都不大，叠加起来就是「习作感」。
8. **进度不保存、无可分享状态**（A③）。Learn Arduino 首屏就有 0/16 进度。我们的导览进度只在会话内，关掉即清零，也没有可分享的链接状态。

## 三、升级规格

工作量档位：S = 半天内；M = 1–3 天；L = 一周量级。每项写明「过」的验收标准，验收一律以截图/实测为准，不以代码自述为准。

### 第一组：先成为产品（两件产品共通）

**U1 · 部署上线**（S）
- 改什么：两件产品部署到公开静态托管（Vercel 或 GitHub Pages），服务器课连同 three.module.js / OrbitControls.js 一起上；继电器课单文件直接上。各给一个稳定短路径。
- 过：任何人（无登录、干净浏览器）打开 URL 能玩；无头 Chrome 拉线上页截图与本地版一致、0 控制台错误；手机宽度打开不白屏。

**U2 · 默认「运行中」状态**（S）
- 改什么：服务器课默认状态改为已上电、负载约 60%、风扇转动、状态灯亮，导览以浮层邀请形式存在而不是让机器关着等点击；继电器课默认保持待机（教学起点成立），但舞台加一条「先看它工作一次」的 8 秒自动演示入口（自动走完 4 步再停回待机）。
- 过：两页首帧截图——服务器课状态为「运行中」且读数非零、相隔 1 秒两帧风扇角度不同（动起来的证据）；继电器课点自动演示后读数走到 100 mA / 120 W 再回落。

### 第二组：服务器课视觉主线

**U3 · 渲染管线升级**（L）
- 改什么：开阴影（PCFSoft，一盏主方向光带阴影 + 补光）、加环境反射（PMREM + RoomEnvironment 或等效环境贴图）、ACES 色调映射；地面换成有边界的机房地砖台面 + 柔和暗角，删掉无限网格；材质按真实分工调 roughness/metalness（拉丝金属、哑光塑料、PCB 阻焊绿）。
- 过：全景与 CPU 特写两张截图里，机器在台面上有可辨的接触阴影、PSU 金属面有明暗渐变、不再有漂浮感；与本文件 server-1/server-4 并排看，差异一眼可辨。

**U4 · 模型保真第二轮**（M）
- 改什么：风扇叶轮换成真实扇叶扫掠造型（双转子观感）；DIMM 加颗粒与标签（canvas 纹理即可）；散热器鳍片加密到特写不露馅；丝印字号缩到真实比例；前面板在默认镜头下能数清 8 个仓位与双灯。
- 过：按 REFERENCES.md 的实拍来源逐项对照特写截图，清单 5 项全过；不再出现星形风扇与玩具字号。

**U5 · 构图与镜头**（M）
- 改什么：默认机位让整机占舞台宽度 ≥55%；6 步导览每步的机位单独定版（既看得到被讲部件、又不把整机裁没）；视角小地图保留但不再压内容。
- 过：逐个截 6 步状态图成 contact sheet，六张里每张主体完整、被讲部件可辨。

### 第三组：内容与深度

**U6 · 服务器课扩课到 6 节**（L）
- 改什么：在现有 3 节后续加：内存与通道实操、RAID 实操课（把模拟器升为一节正式课）、故障排查课（读灯语义+日志定位）；每节保持现有结构（导览+短文+互动题+big idea）。
- 过：课程轮播 6 节齐全，每节互动题可完成且判定正确；单节时长与现有 3 节同量级。

**U7 · 继电器课补题与第三故障**（M）
- 改什么：加 1 道互动题（情景判断：粘连 vs 烧断的读数区分）；加第三个故障「弹簧疲劳」（释放迟滞，部件卡里已埋了这个知识点）；加常闭触点对比小视图。
- 过：题可答且判定正确；三故障各自的读数组合互不相同、与部件卡文案一致。

**U8 · 自由探索模式**（M，服务器课优先）
- 改什么：服务器课加「分解视图」滑杆（导流罩/风扇墙/riser/PSU 沿轴向拉开）+ 盘与风扇模块可拖出拖回；继电器课加脱离导览的自由通断电开关模式。
- 过：不进入导览也能完成一次分解—复原；拖出的盘触发与点击拔盘一致的模型状态。

**U9 · 进度持久化**（M）
- 改什么：localStorage 存导览/课程/答题进度，首屏显示「已学 x/6 节」；状态可经 URL 参数分享（至少含当前课与步）。
- 过：刷新与重开浏览器后进度还在；带参数链接打开直达对应状态。

### 第四组：演示与收尾

**U10 · 继电器课版式小伤修复**（S）
- 改什么：修「负载电流」读数被小地图卡裁切、舞台底部中央控制胶囊与内容重叠两处。
- 过：待机/工作/粘连三态截图里所有读数完整可读、无重叠。

**U11 · 60 秒演示重录（两件产品各一条）**（M）
- 改什么：按 Dilum 结构剪：0 秒即运行中全景 → 导览推进 → 搞坏它 → 修复收尾 → 标题卡（课名+链接）。用最终模型录，不再用旧模型素材。
- 过：抽 0/15/30/45/60 秒五帧成 contact sheet，五帧密度均不低于 Dilum 视频中段帧的观感（主体占比、读数在动、状态可辨）；成片与线上版同一版本。

## 四、建议施工顺序与旗舰推荐

**顺序**：U1 上线 + U2 运行态（先成为产品，一天内可见效）→ U3 渲染 + U4 保真 + U5 构图（服务器课视觉主线，这是与 Dilum 的主差距）→ U11 服务器课演示重录（第一条帖的弹药）→ U6 扩课 / U8 自由模式 / U9 进度（把「一门课」立起来，喂后续更新帖）→ 继电器课 U10 + U7 随后跟上。理由：发帖公式里链接和录屏是硬门槛，视觉是录屏的上限，内容量决定账号能不能持续——按这个顺序，每一步都解锁下一步的价值。

**旗舰推荐：服务器硬件交互课。** 三条理由：①形态对位——它就是 Robin 版的 Learn Arduino（3D 整机+导览+实验室），Dilum 已用 723K 浏览证明这个形态在 X 上成立；②身份壁垒——Dilum 是软件工程师做硬件科普，Robin 是数据中心一线运维做服务器课，REFERENCES 里那套真机溯源和故障症状口径是对方抄不走的；③钩子现成——WareTrack 的「枯燥工业系统游戏化」反差，正对应「机房里的机器也能拆开点着玩」。继电器的定位是**元件系列第二弹**：等旗舰把账号的视觉与质量标杆立住后，用 working-machine 同壳量产元件课（继电器已是第 1 号），形成 Dilum 式的「更新帖」节奏。

**一句诚实话收尾**：现在这两件产品是「内核达标的本地演示」，不是「能发的产品」。差距不在创意和模型——这两样恰恰是最好的部分——而在上线、光影、首帧和体量这四件「成品活」上。按上面顺序补完，服务器课有资格做 @robin_playbooks 的置顶帖；在此之前发帖，等于拿习作去对标人家的成品。
